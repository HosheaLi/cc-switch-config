# Plan 03: Migrate All Consumers from Template* to ApiConfig

## Objective

将所有 TemplateService/TemplateStore 消费者迁移到 ApiService/ApiConfigStore，更新数据结构引用，重构 tui-launch.ts 为 cli-launch.ts，实现数据迁移工具。此计划完成后，代码库中不再有任何 Template* 运行时引用。

## Background

Plan 02 已删除 Template* 源文件和 barrel exports。本计划修复所有因此产生的编译错误，将 7 个消费者文件 + 2 个命令文件 + export-schema 迁移到 ApiConfig 层。RESEARCH.md 确认 ApiConfig CRUD 链路已完整可用，迁移是 wiring 而非 building。

- src/lib/types/api-config.ts (ApiConfig 类型定义)
</read_first>

<action>
对 3 个 wizard 文件执行以下替换：

**导入替换：**
- `import { TemplateService } from '../../../lib/services/index.js'` → `import { ApiService } from '../../../lib/services/index.js'`
- `import { TemplateStore, readConfig, writeConfig } from '../../../lib/store/index.js'` → `import { ApiConfigStore, readConfig, writeConfig } from '../../../lib/store/index.js'`
- `import type { TemplateConfig } from '../../../lib/types/index.js'` → `import type { ApiConfig } from '../../../lib/types/index.js'`

**实例化替换：**
- `new TemplateStore()` → `new ApiConfigStore()`
- `new TemplateService(templateStore, readConfig, writeConfig)` → `new ApiService(apiConfigStore, readConfig, writeConfig)`

**方法调用替换：**
- `templateService.listTemplates()` → `apiService.listConfigs()`
- `templateService.createTemplate(name, { name, description, provider: { name: modelName, baseUrl, authType: 'header', env: { ANTHROPIC_API_KEY: apiKey } } })` → `apiService.createConfig(name, { name, apiKey, baseUrl, mode: 'unified', modelName })`
- `templateService.applyTemplate(projectPath, templateName)` → `apiService.applyConfig(projectPath, configName)`
- `templateService.deleteTemplate(name)` → `apiService.deleteConfig(name)`
- `templateService.getTemplate(name)` → `apiService.getConfig(name)`

**关键字段映射（PATTERNS.md Pattern A）：**
- `TemplateConfig.provider.name` → `ApiConfig.modelName`（不是 `ApiConfig.name`！）
- `TemplateConfig.provider.baseUrl` → `ApiConfig.baseUrl`
- `TemplateConfig.provider.env.ANTHROPIC_API_KEY` → `ApiConfig.apiKey`
- 新增 `ApiConfig.mode = 'unified'`

变量名也需同步重命名：`templateService` → `apiService`，`templateStore` → `apiConfigStore`，`template` / `templates` → `config` / `configs`。
</action>

```typescript
import { readFileSync, existsSync, writeFileSync } from 'node:fs';
import { join } from 'node:path';
import { ApiConfigStore } from './api-config.js';
import { getConfigDir } from './config.js';
import { ApiConfigSchema } from '../types/api-config.js';

// 迁移源类型（简化版，仅用于解析旧数据）
interface LegacyTemplateConfig {
  name: string;
  description?: string;
  provider: {
    name: string;        // 模型名称 → ApiConfig.modelName
    baseUrl: string;
    authType: string;
    env: { ANTHROPIC_API_KEY: string };
  };
  createdAt?: string;
  updatedAt?: string;
}

interface LegacyTemplatesFile {
  version: number;
  templates: Record<string, LegacyTemplateConfig>;
}

export function migrateTemplatesToApiConfigs(): {
  migrated: number;
  errors: string[];
  backupPath: string | null;
} {
  // 1. 检查 templates.json 是否存在
  // 2. 备份 templates.json → templates.json.bak
  // 3. 读取并解析 templates.json
  // 4. 对每个 TemplateConfig 执行字段映射：
  //    - name → name
  //    - provider.name → modelName
  //    - provider.baseUrl → baseUrl
  //    - provider.env.ANTHROPIC_API_KEY → apiKey
  //    - 新增 mode: 'unified'
  // 5. 用 ApiConfigSchema 逐个验证转换结果（Zod strict）
  // 6. 写入 api-configs.json（通过 ApiConfigStore）
  // 7. 删除/重命名 templates.json
  // 8. 返回迁移统计
}
```
