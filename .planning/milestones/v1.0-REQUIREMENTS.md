## Overview

CCAPISwitch 是一个 CLI/TUI 工具，用于管理 Claude Code 的项目级 API provider 配置。解决多项目、多 API 供应商、多模型配置的管理难题，提供可视化、可靠、安全的配置管理体验。

**Core Value:** 一站式配置管理 — 让 Claude Code 的配置变得简单、可靠、可视化。即使工具失效，用户也能快速查看所有项目的配置状态。

**Target Users:** 
- Primary: 个人开发者使用
- Secondary: 开源发布供社区使用

## Functional Requirements

### P1 - Must Have (MVP)

这些功能是产品的基础，缺失会导致产品不完整。

| ID | Feature | Description | Acceptance Criteria |
|----|---------|-------------|---------------------|
| F1 | Profile CRUD Operations | 创建、列出、切换、删除配置 profiles | 用户能完整管理配置生命周期 |
| F2 | Interactive TUI Selector | 箭头键导航、模糊搜索、视觉反馈的交互式选择器 | 用户能用键盘快速选择配置 |
| F3 | Configuration Preview | 应用配置前显示将要修改的内容 | 用户能看到 diff 预览 |
| F4 | List All Projects | 显示所有管理的项目及其配置状态 | 用户能一目了然查看所有项目状态 |
| F5 | Quick Switch Command | `cc-config switch <name>` 一键切换 | 用户能快速执行最常用操作 |
| F6 | Current Status Display | `cc-config current` 显示当前激活配置 | 用户能随时确认当前状态 |
| F7 | Custom Provider Templates | 用户自定义 API 供应商模板，无预定义模板 | 用户能创建自己的模板并复用 |
| F8 | Token Security | API tokens 存于 settings.local.json，检测 git 追踪风险 | 用户不会意外提交 tokens 到 git |

### P2 - Should Have (v1.x)

这些功能提升产品竞争力，建议在核心功能验证后添加。

| ID | Feature | Description | Acceptance Criteria |
|----|---------|-------------|---------------------|
| F9 | Auto-Switch by Directory | 进入项目目录自动应用对应配置 | 用户 cd 到项目目录后自动切换配置 |
| F10 | Project Directory Scan | 自动扫描指定目录发现现有项目 | 用户能快速导入现有项目 |
| F11 | Config Validation | 配置语法检查 + schema 验证 | 用户在保存前收到错误提示 |
| F12 | Diff Before Apply | 应用配置前显示 side-by-side diff | 用户能确认具体变更内容 |
| F13 | Import/Export Configs | 导出配置到文件、从文件导入 | 用户能备份、迁移、分享配置 |
| F14 | Fuzzy Search | 项目/配置列表的模糊搜索过滤 | 用户能快速定位目标配置 |

### P3 - Future (v2+)

这些功能复杂度高或需要更多验证，推迟到产品成熟后考虑。

| ID | Feature | Description | Rationale for Deferral |
|----|---------|-------------|------------------------|
| F15 | MCP Server Management | 管理 MCP 服务器配置 | 复杂度高，需求不够明确，需研究 Claude Code MCP 格式 |
| F16 | API Connectivity Validation | 验证 API endpoint 可达性 | 需研究各 provider 的验证 API，模式不一致 |
| F17 | Pre-defined Provider Templates | 预定义 OpenRouter、Groq 等模板 | 维护负担，容易过时，先验证用户需求 |
| F18 | Bulk Operations | 批量应用模板到多个项目 | 需先验证单项目工作流有效 |
| F19 | Desktop GUI (Tauri) | 桌面应用版本 | 平台扩展，仅当 TUI 有用户需求时考虑 |
| F20 | Multi-level Config Hierarchy | 支持 user/project/local 三层配置优先级 | 高级功能，需用户明确需求 |

## Non-Functional Requirements

### Performance

| ID | Requirement | Metric | Rationale |
|----|-------------|--------|-----------|
| N1 | Fast Startup | < 1 second cold start | CLI 工具必须快速响应 |
| N2 | Quick Operations | < 100ms for switch/list | 核心操作不应让用户等待 |
| N3 | Scalable Scanning | < 5s for 100 project scan | 支持大型项目集合 |
| N4 | Responsive TUI | < 50ms render time | 流畅的交互体验 |

### Reliability

| ID | Requirement | Metric | Rationale |
|----|-------------|--------|-----------|
| R1 | Atomic Writes | Zero config corruption on crash | 配置文件损坏是灾难性故障 |
| R2 | Backup System | Auto backup before every modification | 用户必须能恢复误操作 |
| R3 | Error Recovery | Graceful handling of all file I/O errors | 工具不能因为文件错误崩溃 |
| R4 | Cross-Platform | Works on macOS/Linux/Windows | 用户在不同平台使用 |

### Security

| ID | Requirement | Metric | Rationale |
|----|-------------|--------|-----------|
| S1 | Token Isolation | Tokens never in git-tracked files | API tokens 不能泄露到版本控制 |
| S2 | File Permissions | Config files 600 permissions | 防止其他用户读取敏感配置 |
| S3 | Token Masking | Display only last 4 chars | 日志/截图不泄露完整 token |
| S4 | Input Validation | All user input validated | 防止注入攻击 |

### Usability

| ID | Requirement | Metric | Rationale |
|----|-------------|--------|-----------|
| U1 | Clear Errors | JSON errors with line numbers | 用户能定位并修复配置错误 |
| U2 | Undo Support | Ability to undo any modification | 用户不怕误操作 |
| U3 | Keyboard Navigation | Both arrows + j/k supported | vim 和非 vim 用户都能使用 |
| U4 | Escape to Cancel | Always allow canceling dialogs | 用户不被困在操作中 |
| U5 | Confirmation Prompts | Destructive actions require confirmation | 防止意外数据丢失 |

### Maintainability

| ID | Requirement | Metric | Rationale |
|----|-------------|--------|-----------|
| M1 | Test Coverage | ≥80% for core modules | 代码质量保障 |
| M2 | Type Safety | Full TypeScript coverage | 减少运行时错误 |
| M3 | Schema Versioning | Config schema version field | 支持配置迁移 |
| M4 | Module Separation | Clear layer boundaries | 易于测试和维护 |

## Constraints

### Technical Constraints

| Constraint | Value | Rationale |
|------------|-------|-----------|
| Node.js Version | ≥18.17 | ESM support requirement |
| Module System | ESM (`type: module`) | Modern Node.js standard |
| TypeScript | Required | Type safety critical for config tools |
| Config Format | JSON only | Claude Code uses JSON |
| Storage | Local filesystem only | No cloud dependency |
| Distribution | npm + Git repository | npm for install, Git for source |

### Platform Constraints

| Platform | Requirements |
|----------|--------------|
| macOS | Primary development platform, full support |
| Linux | Full support, tested in CI |
| Windows | Full support, tested in CI |

### Security Constraints

| Constraint | Implementation |
|------------|----------------|
| Token Storage | settings.local.json (plaintext) |
| Git Tracking | Check .gitignore, warn on tracked configs |
| File Permissions | Set 600 on sensitive files |
| No Cloud | No remote API calls except validation |

### Scope Constraints

| Out of Scope | Rationale |
|--------------|-----------|
| Token Encryption | Claude Code itself uses plaintext |
| Cloud Sync | Local-only tool philosophy |
| Multi-User | Single-user tool, no collaboration |
| Pre-defined Templates (v1) | Maintenance burden, defer to v2 |
| Desktop GUI (v1) | TUI first, validate before platform expansion |

## Success Criteria

### Phase 1 Success (Foundation)

- [x] **Atomic writes verified**: Kill -9 during write, config remains valid
- [x] **Backup system works**: Every modification creates timestamped backup
- [x] **JSON errors helpful**: Malformed JSON shows line number and context
- [x] **Cross-platform paths**: Works on macOS, Linux, Windows
- [x] **Config migration works**: v0 config loads and migrates correctly
- [x] **Token security enforced**: No tokens in git-tracked files

### Phase 2 Success (Core TUI)

- [ ] **TUI responsive**: List renders < 50ms
- [ ] **Navigation intuitive**: Users complete tasks without tutorial
- [ ] **Preview accurate**: Diff matches actual changes
- [ ] **Quick switch works**: `switch` command completes < 100ms
- [ ] **Keyboard shortcuts**: Both arrow keys and j/k work

### Phase 3 Success (Project Management)

- [ ] **Auto-switch reliable**: Detects project directory correctly
- [ ] **Scan efficient**: 100 projects scan < 5 seconds
- [ ] **Import/Export complete**: Round-trip preserves all config
- [ ] **Fuzzy search fast**: Filtering < 50ms for 100+ items

### Overall MVP Success

- [ ] **User can manage configs**: CRUD operations work reliably
- [ ] **Config never corrupted**: Atomic writes + backups verified
- [ ] **Cross-platform verified**: CI tests all platforms
- [ ] **Security enforced**: Token leakage prevented
- [ ] **Error messages helpful**: Users can fix their mistakes
- [ ] **First user success**: Tester completes basic workflow without help
